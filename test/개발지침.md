# CodeIndex Test Suite 개발 지침

## 📋 개요

CodeIndex의 핵심 기능들을 검증하기 위한 포괄적인 테스트 스위트 개발 및 운영 가이드입니다.

## 🏗️ 테스트 환경 구조

### 테스트 데이터 구조
```
test/
├── run_test.py              # 통합 테스트 런너
├── data/                    # 레거시 테스트 데이터 (게임 관련)
│   ├── character_stats.h
│   ├── combat.cpp/h
│   ├── Inventory.cs
│   └── ...
├── projects/                # 새로운 테스트 프로젝트들
│   ├── Project1/           # 웹 애플리케이션 프로젝트
│   │   ├── frontend/
│   │   ├── backend/
│   │   └── shared/
│   └── Project2/           # 데이터 처리 프로젝트
│       ├── analytics/
│       ├── pipeline/
│       └── utils/
└── fixtures/               # 테스트 전용 데이터
    ├── settings_templates/
    └── expected_results/
```

### 백업 및 복원 시스템
- **settings.json**: `settings.json.tmp`로 백업
- **data 디렉토리**: `data.tmp`로 백업
- 테스트 완료 후 자동 복원

## 🧪 테스트 케이스 분류

### 1. CLI 기능 테스트 (`--cli-only`)
모든 CLI 옵션이 정상적으로 동작하는지 검증:
- `--help`, `--status`, `--remove`
- `--search-code`, `--get-file-outline`, `--get-chunk`
- `--index-only`, `--query-batch`

### 2. 검색 정확도 테스트 (`--accuracy-only`)
코드 검색의 정확성과 관련성을 검증

### 3. 검색 필터 테스트
`search_code` 옵션들의 동작 검증:
- `--top-k`: 결과 개수 제한
- `--language`: 언어별 필터링
- `--symbol-type`: 심볼 타입별 필터링  
- `--project`: 프로젝트별 필터링

### 4. 코드 업데이트 테스트
증분 빌드 시스템의 정확성 검증:
- 파일 수정 감지
- 청크 재생성
- 벡터 임베딩 업데이트
- 메타데이터 동기화

### 5. 코드 삭제 테스트
파일 삭제 시 데이터 정리 검증:
- 인덱스 정리
- 청크 데이터 삭제
- 메타데이터 정리
- 벡터 스토어 정리

### 6. 프로젝트 삭제 테스트
프로젝트 단위 삭제 시 완전한 정리 검증:
- 프로젝트별 모든 데이터 삭제
- 검색 결과에서 제외 확인
- 프로젝트 필터 동작 확인

## 🔧 테스트 케이스 구현 가이드

### 테스트 케이스 1: 검색 기능 테스트

```python
def test_search_functionality():
    """검색 기능 및 필터 옵션 테스트"""
    
    # 1. MCP 서버 연결 테스트
    test_mcp_server_connection()
    
    # 2. 기본 검색 테스트
    test_basic_search()
    
    # 3. 필터 옵션 테스트
    test_search_with_filters()
```

**검증 항목:**
- MCP 서버 정상 연결
- 기본 키워드 검색 정확성
- `--top-k` 제한 동작
- `--language` 필터링 (python, javascript, cpp 등)
- `--symbol-type` 필터링 (function, class, variable 등)
- `--project` 필터링 (Project1, Project2)

### 테스트 케이스 2: 코드 업데이트 테스트

```python
def test_code_update():
    """증분 빌드 시스템 테스트"""
    
    # 1. 초기 인덱싱
    initial_indexing()
    
    # 2. 코드 수정
    modify_source_file()
    
    # 3. 증분 업데이트
    incremental_update()
    
    # 4. 검색 결과 검증
    verify_updated_content_searchable()
```

**검증 항목:**
- 파일 변경 감지 정확성
- 변경된 청크만 재생성 확인
- 새로운 내용 검색 가능성
- 이전 내용 삭제 확인

### 테스트 케이스 3: 코드 삭제 테스트

```python
def test_code_deletion():
    """파일 삭제 시 데이터 정리 테스트"""
    
    # 1. 삭제 전 검색 확인
    verify_content_exists()
    
    # 2. 소스 파일 삭제
    delete_source_file()
    
    # 3. 증분 업데이트
    incremental_update()

```

**검증 항목:**
- 인덱스에서 파일 정보 삭제
- 관련 청크 데이터 삭제
- 메타데이터 정리
- 벡터 스토어에서 삭제
- 검색 결과에서 제외 확인

### 테스트 케이스 4: 프로젝트 삭제 테스트

```python
def test_project_deletion():
    """프로젝트 단위 삭제 테스트"""
    
    # 1. 프로젝트 데이터 확인
    verify_project_data_exists()
    
    # 2. settings.json에서 프로젝트 제거
    remove_project_from_settings()

    incremental_update()
    
    # 4. 완전한 정리 검증
    verify_project_completely_removed()
```

**검증 항목:**
- 프로젝트의 모든 파일 데이터 삭제
- 프로젝트별 메타데이터 정리
- 프로젝트 필터 검색 시 빈 결과
- 일반 검색에서도 해당 프로젝트 내용 제외

## 🎯 성능 및 품질 지표

### 검색 정확도 지표
- **정확도(Precision)**: 검색 결과의 관련성
- **재현율(Recall)**: 관련 내용의 검색 가능성
- **응답 시간**: 검색 쿼리 처리 속도

### 데이터 정리 지표
- **완전성**: 삭제 시 관련 데이터의 완전한 정리
- **일관성**: 인덱스와 실제 파일 상태의 일치성
- **효율성**: 증분 업데이트 처리 속도
